# Known limitations and assumptions

- **Fixed snapshots:** catalog, stock, campaigns and order dates are supplied snapshots. There is no live storefront, carrier or extraction timestamp. Promotion flags are accepted as snapshot facts; absent dates cannot be guessed.
- **Bounded language understanding:** one main intent per turn, a remembered category/product and four tool/source pairs. A fixed scenario pass does not establish general accuracy or broad multilingual/adversarial robustness.
- **Restricted factual generation:** answers are rendered by Python from queried fields and reviewed policy text. This supports traceability but does not offer open-ended generated explanations or autonomous multi-step planning.
- **Reviewed policy scope:** section/page retrieval supports explicit topics and pinned documents. Arbitrary PDFs are not accepted. Source changes require reviewed translations and new fingerprints. Installments, exactly-R$500 shipping and contact channels contain source ambiguities; the agent discloses them.
- **No execution of customer actions:** refunds, cancellation, deletion, complaint registration and real human notification are not implemented. Missing receipt date, channel and product exclusions prevent automatic return eligibility decisions. Responses never claim those actions occurred.
- **Prototype identity:** locally issued opaque tokens, no external identity provider, expiry/revocation UI or distributed login limiter. Token provisioning is an operator-only utility.
- **Heuristic PII guard:** common contact/secret patterns are withheld, but obfuscation and arbitrary self-disclosure can evade it. Provider privacy/retention settings require review before real customer traffic; `store=False` alone is not a zero-retention guarantee.
- **Local budget scope:** the verification runner guards only requests using its ledger. Direct CLI runs or unrelated applications are outside it unless configured. Usage-price calculations are not invoices. Missing usage retains a conservative reservation; pricing/model changes require review.
- **Reproduction boundaries:** recorded local verification used Windows/Python 3.12. CI covers Python 3.10/3.12 on Linux; remote results are available through the repository's Actions tab. Editable checkout is supported; a standalone wheel does not package the demo data. Direct dependency versions are recorded without a complete transitive lockfile.
- **No graphical interface:** the text CLI is the demonstration interface. A UI is a possible extension after core correctness and identity improvements.
